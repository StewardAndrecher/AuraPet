# AuraPet 1.0.27 发布前架构审查

当前 Qt/C++ 桌面进程与可选千问进程的边界合理。默认播放器、角色库、行为算法、专注状态和 TTS 各有独立模块。用户可以只安装桌面应用，角色包和模型也可以分别升级。此版适合继续迭代，首发无需整体重构。

## 现有边界

| 模块 | 当前形态 |
| --- | --- |
| `PetWindow`、`RandomMovement`、`PetMotionRules` | 桌宠绘制、运动调度和规则分离，适合独立验证 |
| `RoleLibrary`、`role_share`、`role_package` | SQLite、导入事务和 ZIP 格式分离，能保留聊天历史 |
| `FocusSession`、`CompanionEvents` | 专注与休息状态、日常事件和去重分别管理 |
| `ChatSession`、`SpeechPlayback`、`voice/server.py` | 聊天服务与语音可独立选用，系统语音和本地千问走不同后端 |

## 以代码中的实际问题为顺序

1. **把 `main.cpp` 的业务编排拆出。** 入口约 855 行，角色切换、菜单、触发事件、语音准备、显示器设置和快捷键同时捕获局部状态。先提取陪伴事件和角色切换控制器，再集中菜单动作挂接，保持入口只负责对象组装。
2. **把大角色包的准备阶段移到后台。** 导入目前会在弹出预览前读取、校验和解码素材，包体上限 256 MiB。支持后台读取、进度和取消，留在主线程或数据库连接所属线程的操作分别是显示预览与提交。
3. **将界面联调和安装验证纳入常规测试。** 事件冷却、计时恢复、旧包迁移、角色卡选取和安装脚本可以自动验证。多屏拔插、Gatekeeper 和干净系统安装应有独立的发布验收。
4. **整理能复现的公开构建。** 当前发布包用 `AURAPET_RELEASE_ASSETS=ON` 构建，启用原创角色。公开源码时建议让原创资源成为默认，将本机开发素材和个人音色继续留在本地。主程序的 macOS 专用接口可以保持独立，以便后续移植。

此轮新增发布入口、固定模型清单和精简 Metal 桥接。原有本机千问服务和桌面安装无需随测试包更新。
